## Github intro notes

### Git: a distributed version control system which tracks changes and shares, as well as allow people to work together

### GitHub: a way to use git in an easy to use interface, used to collaborate and maintain the history of projects

### Repository: contains all the project files and version history, a kind of project file. Repositories can be navigated best through the github dashboard

### Cloning: allows you to create a local version of your repository and sync the local and cloud repository

### Commiting and Pushing: how you copy the changes you made on the local repository to the cloud repository

### Branches: tools that can be used to make sure work you don't want merged onto your final project yet is isolated from the rest of the project, and the default branch of you repository is the main repository

### Forks: another way to copy your repository, and the way to contribute to someone else's repository

### Pull requests: can be used to tell the other people working on a project what you want to contribute and ask for their opinion on your changes. Can be merged to the main branch once the other collaborators are done reviewing, and you can add specific people as reviewers.

### Issues: a tool that can track enhancements, tasks, and bugs in your work on GitHub, a great way to tell others what you plan to work on

### User profile: tells people what repositories you have worked in and the conversations you've had

### Markdown: a way to add style to your issues and files 

### Extra notes: you can keep in touch with the community by starring communities, following users, and browsing Github itself
